# Design doc

Decisions in, one design doc out: `docs/design/<slug>.html` for people and `docs/design/<slug>.llm.md` for models.
The reader is a developer of the team who was not in the discussion. The doc is written in the language of the
repo's docs (or the user's, when the repo has none).

The HTML is the source. The twin is generated by [scripts/extract-llm.mjs](scripts/extract-llm.mjs) and never edited
by hand: headings, lists, Markdown tables, code, callouts as blockquotes, and each SVG as its `<title>` plus its text
labels. Its first line holds the sha256 of the HTML, so `--check` fails when the HTML changed and nobody
regenerated it. Measured on two real docs: 60k → 21k and 34k → 10k tokens, no word or table cell lost.

Requires:
- The decisions: a plan file, an ADR list, or the conversation. Missing → ask; this skill writes decisions up, it
  does not take them.
- Sibling repos for code claims. Missing → mark each code claim "(not verified in code)".

```
- [ ] 1 Sources    - [ ] 4 Review     - [ ] 7 Publish (optional)
- [ ] 2 Brief      - [ ] 5 Assemble   - [ ] 8 Report
- [ ] 3 Write      - [ ] 6 Route
```

## 1. Sources

- The decisions, plus any paper, canvas or measurement the user points to. Take numbers only with their source; a
  number measured on an older design is labelled as such.
- Code: read the default branch on the remote (`git fetch`, then `origin/<default>`), not the local checkout.
- Repo vocabulary: names the doc must spell one way go in `.design-doc-vocabulary.json` at the repo root
  (`[{"pattern": "regex", "flags": "i", "reason": "..."}]`); the checker applies it. Ask the user for it the first
  time if the repo has product names that are often misspelled.

## 2. Brief

Write the brief once and give it to both subagents:
- The figure list, fixed before anyone starts: `Dxx – title` with one line of content each. The writer leaves an
  `<!-- svg Dxx -->` marker inside each `<figure>`; the diagram author draws the same ids.
- For the writer: the decisions with their why, the numbers with their source, the structure in
  [references/structure.md](references/structure.md), the page in [references/template.html](references/template.html)
  (keep its `<style>` and components), and the rules below.
- Output: `docs/design/<slug>.html` and `docs/design/<slug>-figs/Dxx.svg`.

Writing rules:
- Each section opens with its main idea in one or two sentences, then the detail.
- Each decision is a `.decision` block: Decision, Alternatives, Why. A mistake an implementer will make is a
  `.pitfall` block: what happens, how the design avoids it.
- Worked examples with ids from the case at hand, never customer data.
- Estimates say how they were computed; one unit per quantity (GB or GiB, not both).
- Code blocks carry their language (`<code class="language-sql">`); tables keep the same column count in every row.
- Each figure: a caption `Figure N. What it shows, in one sentence.`, numbered in order.
- Diagrams: one standalone `<svg>` per file with a `viewBox`, a `<title>` that says what the diagram shows (it is
  all a model reads of the drawing, with the text labels), every label as real `<text>` (never paths), the colours
  of the template's `:root`, and unique ids (prefix marker ids with the figure id).
- The writer's final report puts **contradictions between sources and code first**, then every
  "(not verified in code)" claim.

## 3. Write

A short doc (a few sections, one or two figures): write it yourself from the template. Otherwise launch both
subagents in the background in one message: the writer and the diagram author, each with the brief. Do not end
or restart the session until both return.

## 4. Review

- Read the writer's contradictions. Verify yourself, in code, the two or three that change the design or the
  numbers; subagents misread.
- Fix the doc, or move the point to Open questions with an owner. Questions for Product stay open in the doc for
  Product to answer; do not answer them for Product.

## 5. Assemble

```bash
node <skill>/scripts/inline-figures.mjs docs/design/<slug>.html   # pastes <slug>-figs/Dxx.svg into each marker
node <skill>/scripts/theme.mjs --apply docs/design/<slug>.html    # writes the theme's colours and fonts into the page
node <skill>/scripts/extract-llm.mjs docs/design/<slug>.html      # writes <slug>.llm.md
node <skill>/scripts/check-doc.mjs docs/design/<slug>.html        # OK, or every problem
```

`<skill>` is this skill's folder. Delete `<slug>-figs/` once the figures are inlined: the SVG now lives in the
HTML. The checker covers the routing comment, figures (SVG `<title>`, caption numbering, markers left), table row
widths, empty sections, duplicate ids, broken `#` links, code languages, template placeholders, the repo
vocabulary and a stale twin. Fix and re-run until it prints OK.

**Theme.** The page takes its colours and fonts from the first theme found: `--theme <css>`, the nearest
`.design-doc-theme.css` up to the repo root, the theme of the org profile that matches the repo's `origin`, then the
built-in one. A theme is one `:root { }` block of the tokens in `template.html` (`--ink`, `--accent`, `--font-sans`…),
optionally after `@import` or `@font-face`; a missing token is reported by name. Figures use `var(--accent)` and the
other tokens, never literal colours; `check-doc.mjs` flags a colour the theme does not have and takes the same `--theme`.

Every later change to the doc: edit the HTML, run `extract-llm.mjs`, commit both files together.

## 6. Route

So agents read the twin and not the HTML:
- Line 1 of the HTML is the comment from the template: `<!-- For agents: read <slug>.llm.md instead of this file
  ... -->`. A Read of the HTML still costs the whole file; the comment only stops the agent from reading further.
- The first time in a repo, copy `scripts/extract-llm.mjs` to the repo's `scripts/` and add this line to its
  `AGENTS.md` (and `CLAUDE.md` if it has one):

  > Design docs: `docs/design/<name>.html` is for people. Read its twin `<name>.llm.md` (same content, about a third
  > of the tokens). Open the HTML only to change the doc, then run `node scripts/extract-llm.mjs <file>` and commit
  > both.

- If the repo has CI or a pre-commit hook, add `node scripts/extract-llm.mjs --check docs/design/*.html`.
- `route` mode (a repo with HTML docs and no twins): do the three steps above and run `extract-llm.mjs` on each
  doc. Validate a new kind of doc first: compare the twin's words and table cells with the HTML's text.

Do not hide the HTML with ignore rules: it is the source, and these rules also stop the agent that edits it.
Checked against the docs on 2026-11-20:
- Claude Code `permissions.deny` `"Read(/docs/archive/**)"` in `.claude/settings.json` (`/` is the project root)
  also blocks Edit and Write there, applies best-effort to Grep and Glob, and to `cat`/`head`/`tail`/`sed` that name
  the file; not to a `grep -r .` that does not name it, nor to scripts.
- Cursor `.cursorignore` blocks the Agent, Tab and @-mentions; the docs say terminal and MCP tools are not blocked
  and do not say whether semantic search honours it.

Use them for folders no agent should read (archives, closed tickets), never for a doc's source.

## 7. Publish (optional)

- **PDF:** `node <skill>/scripts/render.mjs docs/design/<slug>.html --pdf` prints the page as it is (the template's
  print CSS paginates parts and keeps figures and tables whole), or print it from a browser.
- **Export figures:** `bash <skill>/scripts/setup.sh` once (Playwright goes to `~/.cache/gutix`; it drives the system
  Chrome or Chromium, `CHROME_PATH` overrides), then `node <skill>/scripts/render.mjs docs/design/<slug>.html --png`
  writes one themed PNG per figure, 2x (`--scale 1`..`4`), as `<slug>-<figure id>.png`. A single `.svg` works too.
  The render refuses a figure below 400x120 or more than 4:1 stretched: fix the viewBox, not the lint.
  Export renders without JavaScript and loads only inline data and fonts: remote or relative images do not appear.
  A doc you do not trust can still make the export fetch web fonts and stylesheets over https.
- **Google Doc:** one rule: paste the twin, then insert the PNGs. Put the twin without its first line on the
  clipboard (`tail -n +3 <slug>.llm.md`, piped to the first of `pbcopy`, `wl-copy`, `xclip -selection clipboard` that
  exists; with none of them, tell the user the twin's path and have them copy the file), then in the doc: Tools →
  Preferences → "Enable Markdown", Edit → "Paste from Markdown". Insert each exported PNG where its figure goes
  (Insert → Image → Upload from computer). Doc tools that take the content as an argument make the model re-type it:
  above ~30 KB, paste instead.
- Never upload internal diagrams to a public host to insert them as images.

## 8. Report

Say where the HTML and the twin are, that `check-doc` printed OK, and what is left: open questions with their owner
and claims not verified in code.

## Anti-patterns

- Editing the `.llm.md` by hand, or committing the HTML without regenerating it.
- Saying "the doc is done" when only a local draft exists, or before `check-doc` prints OK.
- A diagram whose labels are paths or images: the twin gets nothing from it.
- Re-typing SVGs into the HTML instead of `inline-figures.mjs`.
- Repeating a number from a canvas or paper without saying which design and date it measured.
- Putting the HTML in `.cursorignore` or a `Read` deny rule.
