# T-03: pr-review: attention map, what checks prove, human-read paths

- **Roadmap:** ../ROADMAP.md · **Phase:** 1 · **Repo:** gutix · **Base branch:** master · **Branch:** feat/human-ownership-p1
- **Depends on:** T-02 (the skill it hands to) · **Model:** main · **Principles:** P4, P5

## Goal
A pr-review report tells Nicolas not only the bugs but where a human must still read and what the green checks don't
cover, and hands release PRs to sign-off. Tests that only mirror the implementation get caught.

## Scope
- `skills/pr-review/repo-rules-template.md`: add the `## Human-read paths` section from the roadmap's Contracts.
- `skills/pr-review/SKILL.md`:
  - Step 1: read `Human-read paths` with the invariants.
  - Step 3, "intent and tests" reviewer: compare the tests with the spec or acceptance criteria; flag tests that assert
    what the code does rather than what was asked, and behaviour no test reaches.
  - Step 5 report: add "attention map" (human-read hunks, `file:line`, even with no findings) and "what the checks
    prove and don't".
  - Close (D10): release PRs go to `gutix:sign-off` before merge; other PRs that touch human-read paths get it
    offered, not required.
  - Trim elsewhere so the file grows by ≤ 8 lines.
- `skills/pr-review/catalog.md` → Intent: one line on tests that mirror the implementation.
- Out of scope: the peer review skill (removed in 0.9.0) (it reuses steps 2–5 and gets this for free; check it still reads right, don't edit it
  unless it breaks).
