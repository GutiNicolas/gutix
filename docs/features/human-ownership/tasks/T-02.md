# T-02: New skill gutix:sign-off

- **Roadmap:** ../ROADMAP.md · **Phase:** 1 · **Repo:** gutix · **Base branch:** master · **Branch:** feat/human-ownership-p1
- **Depends on:** T-01 (Result headings, release line) · **Model:** main · **Principles:** P4, P5, P6, P8, P10

## Goal
Before a release (or a PR in human-read paths) merges, Nicolas gets one page that shows what was expected against what
was built, what the agents decided, the hunks to read, what the checks don't prove, and a short quiz that Nicolas
answers and the agent grades. `brief` mode is the same page without the quiz, to catch up after time away.

## Scope
- `skills/sign-off/SKILL.md` (≤ 80 lines), frontmatter like the other skills: args `target`, `since`, `mode`.
  Description triggers: before merging a release PR or a PR that touches human-read paths; to catch up on a feature
  or PR after time away ("where was I", "what changed since").
- Inputs, cheapest first: the roadmap (Hypothesis, Definition of done, release line), the task Results, `git diff
  <since>..<head> --stat` then the human-read hunks only, the pr-review report if one exists, `gh pr checks`.
- Human-read paths from `.claude/review.md`, else the default list in the roadmap's Contracts.
- Rules the skill must state:
  - The agent never answers its own quiz and never shows the answers before Nicolas has answered.
  - Questions need the attention-map hunks to answer, not the summary: no yes/no, each tied to `file:line`.
  - Decisions that appear in the diff but in no task Result are flagged as "undeclared".
  - Record only on pass, and record the signed-off sha (the reviewed head), not the commit that writes the record.
    An explicit "merge anyway" from Nicolas is recorded as `override` in the Log, never silently.
  - Section 1 also says what changed in how the system works since the last sign-off, in a few lines.
  - Open areas carry over (D13): read them from the release line, ask them first, keep an area open until a later
    question on it is answered right; a wrong answer gets the explanation and, if Nicolas asks, a deeper one.
  - No roadmap: the fallback in the roadmap's Contracts ("No roadmap").
  - Models (D9): sections 2–4 are collected by a Haiku subagent (task Results, diff stat against human-read paths,
    `gh pr checks`) and returned as a short list; the session itself (Sonnet or main) reads the hunks, flags undeclared
    decisions, writes the quiz and grades it. `brief` mode may run entirely on Haiku.
- Out of scope: posting on the PR (only with Nicolas' yes, D7); changing pr-review or feature-intake (T-03, T-04).

## Contract
ROADMAP.md → Contracts: `gutix:sign-off` (output sections 1–6, modes, record format).

## Acceptance criteria (executable)
- [ ] Skill exists and is small — `wc -l skills/sign-off/SKILL.md` ≤ 80
- [ ] Every output section is there — `for h in 'Expected vs built' 'Decisions and assumptions' 'Attention map' 'Checks' 'Quiz' 'Record'; do rg -qF "$h" skills/sign-off/SKILL.md || echo "MISSING $h"; done` prints nothing
- [ ] Modes and catch-up — `rg -n "since|brief" skills/sign-off/SKILL.md` shows the `since` arg and the `brief` mode
- [ ] The human does the work — `rg -n -i "never answer|before .* answered|override" skills/sign-off/SKILL.md` shows the three rules
- [ ] Carry-over — `rg -n -i 'open area' skills/sign-off/SKILL.md` shows reading, asking first and recording them
- [ ] Model split stated — `rg -n -i 'haiku' skills/sign-off/SKILL.md` shows the collection step, and no line puts the quiz or grading on Haiku
- [ ] Plugin valid — `claude plugin validate .`
- [ ] No-roadmap fallback, from the working tree (the installed plugin is still 0.6.0 until T-05) — `claude --plugin-dir . -p "/gutix:sign-off mode=brief since=4cbfae1"` on gutix master produces sections 1–4, reports "no stated intent" or the PR intent, marks decisions undeclared and records nothing (paste the headings and the attention-map lines under Evidence). The roadmap path is exercised in T-05.
